Add a new exported function `claimNextJob(workerId: string)` to db.ts. This replaces `getNextQueuedJob()` for production use.

Implementation (per D-06 — CAS pattern):
1. Use `getDb().transaction()` to wrap the SELECT + UPDATE in a single transaction (SQLite transactions are serialized, preventing race conditions)
2. Inside the transaction:
   a. `SELECT * FROM jobs WHERE run_status = 'queued' ORDER BY created_at ASC LIMIT 1` — find the oldest queued job
   b. If no row found, return `undefined`
   c. `UPDATE jobs SET run_status = 'spawning', sandbox_pid = ? WHERE id = ? AND run_status = 'queued'` — the CAS (Compare-And-Swap) check in the WHERE clause ensures only one worker can claim
   d. If `result.changes === 0`, another worker claimed it first — return `undefined`
   e. If claimed successfully, return the row (with store_profile and budget_json parsed, same as `getJob()`)
3. Use `process.pid` for the `sandbox_pid` parameter (passed as `workerId` argument is the pid)
4. Parse `store_profile` and `budget_json` JSON fields before returning (same pattern as `getJob()`)

Keep `getNextQueuedJob()` as-is (used by tests or other consumers), but it will no longer be called by worker.ts.

The function signature:
```typescript
export function claimNextJob(): any | undefined {
  const database = getDb()
  const claim = database.transaction(() => {
    const row = database.prepare(
      "SELECT * FROM jobs WHERE run_status = 'queued' ORDER BY created_at ASC LIMIT 1"
    ).get() as any
    if (!row) return undefined
    const result = database.prepare(
      "UPDATE jobs SET run_status = 'spawning', sandbox_pid = ? WHERE id = ? AND run_status = 'queued'"
    ).run(process.pid, row.id)
    if (result.changes === 0) return undefined
    row.store_profile = JSON.parse(row.store_profile)
    row.budget_json = JSON.parse(row.budget_json || '{}')
    return row
  })
  return claim()
}
```
